Branch: main (published), with local feature branches retained · Delivery: static site · Runner: npm test / npm run build

## Specs
S1. “Pedir algo → proporcionar contexto → conectar herramientas → organizar el trabajo → verificar resultados → construir un sistema.” Recorrido guiado y exploración libre, sin sincronización entre dispositivos.
S2. “Agregar un formulario de registro a una aplicación web, con validaciones, integración con una API y pruebas”. Ejemplo compartido en toda la experiencia; contenido en español.
S3. Atlas con Prompt, Contexto, Modelo de lenguaje, Herramientas, Agente, Loop, Workflow, Skills, Hooks, MCP, Harness, Estado y memoria, Validaciones y evaluaciones, Permisos y revisión humana; cada concepto incluye definición, función, piezas, ejemplo, interacción, relaciones y confusión frecuente.
S4. Laboratorio con “Ejecutar simulación · Siguiente paso · Pausar · Reiniciar”, configuración de ocho controles y límite de iteraciones; tres escenarios: éxito, fallo y corrección, aclaración. Todos los resultados “simulados y predefinidos”, sin API ni claves.
S5. Mapa interactivo con conexiones etiquetadas, nodos seleccionables, animación paso a paso, leyenda, vistas simple/detallada y alternativa legible en lista.
S6. SDD y ODD explicados con fuente atribuida, artefactos, iteración y validación; ODD según https://jokiruiz.com/inteligencia-artificial/que-es-odd-organic-driven-development/ sin presentarlo como estándar universal.
S7. Diseño responsive móvil y proyección, navegación por teclado, foco visible, movimiento reducido, progreso local, glosario y enlaces directos.
S8. React + TypeScript + Vite, contenido separado, simulación con transiciones explícitas, compilación y pruebas verificadas, instrucciones de ejecución y despliegue estático.
S9. “No tomaste en cuenta la estructura que te habia compartido del texto es importante porque sera mi guia para continuar la platica”. The guided path must follow the speaker’s didactic sequence; the atlas and simulator remain available for free exploration.
S10. “Empezamos pidiéndole algo a una IA. Después copiamos instrucciones, agregamos contexto, conectamos herramientas y buscamos que compruebe su trabajo. ¿En qué momento dejamos de escribir prompts y empezamos a diseñar un sistema?” Start with the early-chat narrative; teach “Concepto de promp,  promp system y promp engineer” and “Estructura de un buen promp y lo que debe de tener” in an interactive example.
S11. Present project/global instructions and context engineering with `AGENTS.md` and the exact six example names `projectbrief.md`, `productContext.md`, `systemPatterns.md`, `techContext.md`, `activeContext.md`, `progress.md`; include “Definicion de Context Engineer, buenas practicas modernas y boilerplate para claude y gpt.” Explain platform-dependent naming and loading.
S12. Explain finite context and compaction with “Como funciona la memoria de contexto de un LLM (Animacion y ciclo de como es cuando )” and “Que es la compactacion de memoria”; demonstrate Markdown-first ADR/DECISIONS, CHANGELOG/TRACE/PROGRESS and provenance, then optional MCP-backed memory and indexing without asserting unsupported vector features of Engram.
S13. Show why third-party development tools motivate MCP, including Postman, end-to-end tests, databases and Jira as illustrative capabilities; teach host/client/server/tool/resource, permissions, and examples of existing developer integrations. Follow with loop, skills, sub-agents and hooks as a didactic progression, not an invented universal chronology.
S14. “Requiero un diagrama animado e interactico de como funcioan el harness con las piezas previas”. The diagram must show agent/model, loop, skills, sub-agents, hooks, MCP and guardrails as optional/interacting parts, with controls, labels and an accessible list.
S15. “Requiero un diagrama de como funciona esta metodologia”. Add an interactive, animated SDD flow from requirement to specification, plan, tasks, implementation and verification, with each artifact and a feedback path. Keep ODD attributed to the previously verified Joaquín Ruiz article and distinguish general methodology from specific implementations.
